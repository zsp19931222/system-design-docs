# 系统设计文档示例（system-design-docs）

一套「系统设计文档」的示例交付物，用于演示一个交付级文档包应包含什么、长什么样、怎么用。

示例对象：**数据异地备份恢复系统（data-backup）** —— 面向运维与 DBA 的数据库备份 / 恢复管理平台，Web 端配置备份任务，经 SSH 在被备份数据库服务器上执行备份恢复脚本，备份文件落到 SFTP 异地存储（TiDB 走 MinIO/S3），并对备份文件、操作记录、脚本版本统一管理。

> 本仓库只放文档，不含任何源码。文档中的 IP、端口、域名等按「待确认项」标注，样例地址来自联调环境，不可直接当生产配置使用。

## 使用方法

### 查看实施文档

直接用 PDF 阅读器打开 `示例文档/实施文档_v1.0.0.pdf`。文档内图位置以「HTML 交互原件 / SVG 矢量原件」方式引用，便于在评审时放大查看。

### 查看交互式图谱

`系统架构图.html`、`业务流程图.html` 都是**单文件 HTML**，无需构建、无需服务器：

- 双击用浏览器打开即可；
- 支持深色 / 浅色主题切换（首次按系统偏好自动选择）；
- 支持节点高亮、悬停提示、按语义类型筛选关系、Trace 动效回放；
- 内置 PNG / SVG 等格式导出，导出的图片可直接回填进实施文档或 PPT；
- 仅 Google Fonts 走网络，断网时自动降级为系统等宽字体，不影响阅读。

也可通过 URL 参数控制初始状态，例如 `系统架构图.html?theme=light`（`theme=light|dark`、`embed=1` 去工具栏嵌入、`present=1` 演示模式）。

## 文档编写约定

- **单一事实来源**：组件、端口、配置项均从代码与配置取证后写入，不凭印象填写。
- **待确认项显式标注**：生产域名、IP、账号密码等现场才能确定的值统一写 `<待确认：xxx>`，并在「9.5 待确认项汇总」集中列出，避免被误当作已确认信息。
- **不写不存在的东西**：文档只描述项目里真实存在的框架、中间件与依赖（例如本项目不部署 Nacos / RocketMQ / XXL-JOB，就明确写明「不部署」及原因）。
- **风险点写清后果**：如目标机缺 `br`、`mysqldump`、`expdp` 时脚本直接失败，会写到「缺失后果」一列。
- **图与文分离**：拓扑、流程用可交互 HTML 承载，正文只留摘要与引用，便于后续单独更新。

## 复用方式

把本仓库当作模板：

1. 用实施文档九章大纲作为检查表，逐项补齐自己项目的信息；
2. 用架构图 / 流程图替换为自家系统的组件与流程（示例由 archify 生成，支持 Mermaid flowchart / sequenceDiagram / stateDiagram 输入）；
3. 保留「待确认项汇总」与「验证清单」两节，它们决定了文档能否直接用于现场实施与验收。
